Primero: ¿qué problema resolvemos?

  • Una dashboard en Flask con todas las gráficas del proyecto.
  • Una conclusión general debajo de las visualizaciones.
  • Una interfaz ordenada (Bootstrap + pequeños ajustes CSS).

La solución en el repositorio:

  1. Python + Pandas leen el Excel y preparan datos.
  2. Matplotlib dibuja en el servidor.
  3. Cada imagen se codifica como data:image/png;base64,... para el HTML (sin guardar PNG sueltos).
  4. Flask arma la respuesta.
  5. Bootstrap estructura navbar, grid, cards y tipografía.

Parte 1 — ¿Qué es Flask?

Flask es un microframework web para Python: hace de servidor HTTP (en clase, puerto típico 5000), recibe la petición y devuelve HTML, JSON u otros contenidos.

Orden habitual de diseño: URL → función Python → plantilla HTML. En este repo, la carpeta src/ concentra lógica de datos; templates/ la presentación.

Estructura (resumen)
flask_parcial_3/
├── app.py                 ← rutas HTTP, render_template
├── templates/
│   └── dashboard.html     ← vista Jinja (huecos rellenados por el servidor)
├── data/
│   └── ...xlsx
└── src/
    ├── analysis.py        ← carga Excel + menú consola (opcional)
    └── dashboard_service.py  ← gráficas Base64 + KPI + conclusión

Cliente ↔ servidor en 7 pasos

  1. Escribís http://127.0.0.1:5000/ en el navegador.
  2. El navegador envía un GET a /.
  3. Flask encuentra la ruta registrada con @app.route("/").
  4. Se ejecuta la función dashboard().
  5. Se arma un diccionario de contexto (stats, imágenes, conclusión).
  6. render_template fusiona datos + dashboard.html.
  7. El navegador muestra el HTML final.

Piezas imprescindibles en app.py

  • from flask import Flask, render_template
  • app = Flask(__name__) — indica el “núcleo” de la app y dónde buscar templates/.
  • @app.route("/") — el decorador “engancha” la URL con la función.
  • if __name__ == "__main__": app.run(...) — solo al ejecutar el archivo directamente.
@app.route("/")
def dashboard():
    ctx = construir_contexto_dashboard(str(DATA_PATH))
    return render_template("dashboard.html", **ctx)

El operador **ctx expande el diccionario como argumentos con nombre hacia la plantilla (stats=..., conclusion=..., etc.), sin listarlos uno a uno.

FragmentoQué hace en práctica
if __name__ == "__main__" Solo arranca el servidor si corrés python app.py.
debug=True Mejor feedback en desarrollo; no usar así en internet público.
host="127.0.0.1" Solo tu máquina; para red de laboratorio a veces se usa 0.0.0.0 con permiso.

Parte 2 — Jinja2: {{ }} y {% %}

Flask usa Jinja2 para las plantillas. Las variables del servidor se insertan con dobles llaves. 

<img src="{{ img_nacionalidades }}" alt="..." />

Ese valor ya llega como cadena completa data:image/png;base64,... lista para el atributo src.

Ejemplo de lógica condicional (evitar mostrar “vacío” si no hay promedio):

{% if stats.edad_promedio is not none %}
  {{ stats.edad_promedio }}
{% else %}
  —
{% endif %}

No es un lenguaje nuevo: es un motor de plantillas que mantiene el HTML legible.

Parte 3 — Bootstrap en este proyecto

Bootstrap aporta grid 12 columnas, navbar, cards y utilidades (mb-4, text-muted, etc.) cargadas por CDN en dashboard.html.

El bloque <style> propio (.hero, .chart-card, .metric) personaliza sombras, radios y fondo sin reescribir todo el layout: Bootstrap = estructura, CSS corto = identidad visual del equipo.

Profundidad visual: abrí también guia-bootstrap.html (tablas, snippets y checklist UI).

Parte 4 — Qué hace cada módulo importante

src/analysis.py — datos compartidos

cargar_datos(ruta) lee el Excel, renombra columnas y convierte fechas con pd.to_datetime(..., errors="coerce", dayfirst=True). Eso evita caídas por fechas raras y respeta formato día/mes frecuente en Latinoamérica.

Las funciones con plt.show() sirven para el menú consola; el dashboard web usa la misma limpieza pero genera PNG en memoria en dashboard_service.py.

src/dashboard_service.py — gráficas y texto

  • matplotlib.use("Agg"): backend sin ventana — necesario en servidor.
  • _fig_to_base64_uri: PNG → Base64 → prefijo data:image/png;base64,.
  • Cuatro funciones de gráfica + estadisticas_resumen + texto_conclusion.

KPI antes de las gráficas

Mostrar números clave arriba (“ejecutivo primero, evidencia después”): totales, rango de años, edad media, año pico. Formato _fmt con miles separados mejore lectura en la UI.

Archivo de datos ausente

if not DATA_PATH.is_file():
    return (mensaje, 500)

Código HTTP 500 indica fallo de servidor; aquí comunica rápido que falta el Excel en data/. Podría mejorarse con una plantilla de error “amigable” en una iteración futura.

Parte 5 — Qué memorizar para oral rápido

  1. Flask = microframework: rutas + función + plantilla.
  2. La plantilla no es estática: Jinja la completa en el servidor.
  3. Bootstrap = layout rápido por clases; tu CSS corto añade marca.
  4. Agg + Base64 = estadística en el servidor → imagen embebida sin archivos temporales sueltos.
  5. analysis.cargar_datos unifica limpieza entre consola y web.

“Cargamos un Excel, limpiamos con pandas, reproducimos los mismos análisis que en consola, convertimos cada gráfica a imagen en memoria y servimos una sola página HTML con Flask, KPI y conclusión, maquetada con Bootstrap.”

Parte 6 — Checklist para correr y depurar

  1. pip install -r requirements.txt
  2. Excel en data/ con el nombre que usa app.py.
  3. python app.py desde la raíz del proyecto.
  4. Navegador: http://127.0.0.1:5000/
  5. Deberías ver KPI, cuatro gráficas y conclusión.

Cierre

Este proyecto integra datos, servidor web y presentación responsive en un alcance típico de parcial: no es despliegue industrial en la nube, pero sí una base clara para explicar capas cliente–servidor y separación de responsabilidades (src vs templates).

Mejoras opcionales: segunda ruta informativa, plantilla de error 500, caché de gráficas, o charts en el cliente con Plotly (más JavaScript).
